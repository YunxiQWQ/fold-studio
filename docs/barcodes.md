# 条形码

工具栏“条形码”添加一个可编辑矢量组，右侧“编码内容”选择制式。当前提供 14 个入口：

| 用途 | 制式 | 输入 |
| --- | --- | --- |
| 商品零售 | EAN-13、EAN-8、UPC-A | 主体数字可自动补齐校验位；完整编码校验末位 |
| 压缩零售码 | UPC-E | 6 位主体，或含号码系统 0／1 及校验位的完整 8 位 |
| 通用与物流 | Code 128 自动、A、B、C | 自动／B 支持常用半角字符；A 为 ASCII 32–95；C 为偶数位数字 |
| 通用标识 | Code 39、Code 93 | 大写字母、数字、空格及 `- . $ / + %` |
| 外箱 | ITF-14 | 13／14 位数字，校验末位，绘制承载横条 |
| 交叉二五码 | ITF | 偶数位数字，不额外添加校验位 |
| 供应链字段 | GS1-128（EAN-128） | 按括号 AI 输入，见下方支持范围 |
| 库德巴码 | Codabar | A–D 起止字符，主体为数字及 `- $ : / . +` |

每种制式有独立提示和“填入当前制式的示例”。切换制式不自动替换现有内容，也不删除字符、改写大小写或补零；输入无效时保留上一次有效图形，显示具体原因。示例仅在点击按钮后填入。

条码内容、本机生成与校验均在浏览器内完成。条码颜色、白底／透明底、识别文字开关、上下位置、字体及相对字号均可修改。OCR-B 使用本机字体，没有安装时回退等宽字体；条纹本身不依赖 OCR 字体。宽高仍由现有“位置与尺寸”控制，不另设一套缩放系统。左右静区跟随制式保留；批量排布复用现有“排列与变换 → 阵列复制”。

## GS1-128 的范围

- `(00)`：18 位 SSCC，含校验位；当前作为单独字段。
- `(01)`：14 位 GTIN，含校验位；作为商品字段的首项。
- `(10)`、`(21)`：批次／序列号，1–20 位 GS1 半角字符。
- `(11)`、`(15)`、`(17)`：生产／最佳使用／有效期，格式 YYMMDD；DD=00 表示月底。

例如：`(01)09506000134352(10)LOT42(21)SER1`。括号用于人读文本，不编码为数据；开头加入 FNC1，可变长字段后仍有字段时补 FNC1 分隔。拒绝未支持的 AI、重复字段、错误校验位、无效日期与超长内容。此处支持上述常用字段，不是完整 GS1 AI 字典或全业务规则验证器。

EAN-2／EAN-5 附加码、ISBN 专用输入、其他 GS1 AI、流水号批量生成及脚本中的专用窄条宽度补偿不在本轮范围内。编码校验不查询商品注册信息。

## 工程与导出

条纹是 SVG 路径，识别数字是文本；导出不把条码转成位图。生成器设置随 `.fold` 和含折间工程信息的 SVG 保存，恢复草稿、重新打开后继续编辑。移动、旋转或缩放后的变换在更新条码内容时保留。解组后可以按普通矢量元素编辑。

旧 EAN-13／Code 128 工程无需转换。修复原更新逻辑只取首个绘图元素、可能清空整组的问题，并防止第一次编辑被迁移前的旧图层元数据覆盖。二维码沿用原功能，共用更新逻辑的修复也覆盖二维码。

## 实现与验证

追加制式使用 [JsBarcode](https://github.com/lindell/JsBarcode) 3.12.3（MIT），不分发用户提供的 Illustrator 编译脚本或 OCR 字体。许可随在线和离线构建提供。GS1 字段格式参考 [GS1 官方 AI 数据](https://ref.gs1.org/ai/)。

`npm run test:barcodes` 使用独立 ZXing / ZXing-C++ 解码器核对实际条纹；ZXing-C++ 的 WASM 只用于测试，从本地依赖加载，不进入应用，也不请求 CDN。浏览器专项核对 14 个选择项和实际 SVG 图像的扫码结果，以及文字设置、无效输入、变换保留、撤销／重做、保存／重开、SVG 导出和内面条码。离线版运行同一组检查并断言零 HTTP 请求。
